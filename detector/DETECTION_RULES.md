# 检测规则

## 1. 总体原则

工具检测 GitHub PR 范围内可直接观察到的编码 Agent 痕迹。任意已登记规则命中，该 PR 即记为 `agent_trace_detected`；否则为 `no_trace_detected`。数据未完成采集时输出 `unavailable`。

检测只使用显式启发式规则，不使用 LLM、embedding、语义分类器、打分或阈值。

`config/rules/agents.json` 是唯一机器规则源。

## 2. 三类检测证据

### Identity

Identity 覆盖四种输入：

1. PR author identity；
2. commit author identity；
3. PR body / commit message 中 attribution grammar 抽出的 target；
4. 已登记的结构化 commit-message 身份声明。

PR author 与 commit author 都渲染为：

```text
login | name <email>
```

然后使用同一张 `identity_patterns` 扫描。

文本 attribution 也使用完全相同的 `identity_patterns`，不维护第二套 text rule。

### Branch

只检查 PR `head_ref_name`，使用 `branch_patterns`。

### Label

只检查 PR 当前 labels，使用 `label_patterns`。历史 label event 不参与检测。

## 3. Attribution grammar

PR body 和 commit message 逐行处理。先识别 attribution prefix，再抽取 target，最后从 target 起点使用统一 Identity matcher。

普通前缀为：

```text
VERB_PATTERN + 至少一个空格 + CONNECTOR
```

当前动词模式：

```text
generated
implemented
authored
developed
written
created
assisted
built
made
coded
produced
co-authored / co authored / coauthored
co-developed / co developed / codeveloped
```

当前连接词：

```text
by
with
using
via
```

另外登记三种已有固定连字符形式：

```text
Generated-by
Co-authored-by
Co-developed-by
```

普通前缀和连字符前缀之后，matcher 统一允许可选冒号：

```regex
[ \t]*:?[ \t]*
```

因此以下形式都可进入同一 target extraction 流程：

```text
Generated by Claude Code
Generated by: Claude Code
Generated-by Claude Code
Generated-by: Claude Code
Co-authored with Kiro
Co authored by Kiro
Coauthored using Kiro
Co-authored-by: Kiro
```

## 4. Bridge

对已登记的辅助短语，在定义 target 前先消费 bridge：

```text
assistance from
the assistance of
help from
the help of
```

例如：

```text
Authored with assistance from Codex
Developed with the assistance of Junie
Built with the help of Augment Code
```

最终 target 分别从 `Codex`、`Junie`、`Augment Code` 开始。

Bridge 是有限的显式 grammar，不扩展为自然语言理解器。

## 5. Target matching

Attribution grammar 只确定“这里是身份声明上下文”，不直接判断 Agent。

抽出的 target 必须从起点匹配统一的 `identity_patterns`。不对剩余文本做任意 Agent substring search。

文本只做有限的表示层归一化：

```text
[visible](URL) -> visible (URL)
**Agent** -> Agent
__Agent__ -> Agent
*Agent* -> Agent
_Agent_ -> Agent
```

只移除 attribution target 起点处成对的粗体/斜体标记；不移除反引号代码标记。URL 保留，原始证据文本不修改。

## 6. 结构化 message signature

当前只有两条：

```regex
(?m)^🤖\s*Plandex\s*→
(?mi)^Replit-Commit-Author:\s*Agent\s*$
```

它们只扫描 commit message。虽然实现上是独立 signature pattern，但在结果分类中记为 Identity 证据。

## 7. Branch 与 Label

Branch / Label 使用独立显式正则，不进入 Identity matcher。

例如：

```regex
(?:^|/)codex/
(?:^|/)trae/agent-
^codex$
```

## 8. 行为者归属

Identity 证据根据数字 actor id 区分：

- `target_author`：目标 PR 作者；
- `other_author`：PR 中其他 commit 作者；
- `unknown`：无法可靠确定行为者。

Branch / Label 记为 metadata，不自动归因给目标作者。
