# 检测规则

## 1. 总体原则

工具检测 GitHub PR 范围内可直接观察到的编码 Agent 痕迹。任意已登记规则命中，该 PR 即记为 `agent_trace_detected`；否则为 `no_trace_detected`。数据未完成采集时输出 `unavailable`。

PR 的 Agent 结果使用集合语义：同一 Agent 无论命中多少条规则，在 `tools` 中只出现一次。`evidence_count` 仅表示可审计证据行数，不参与状态判断、Agent 归类、权重或使用强度计算。

检测只使用显式启发式规则，不使用 LLM、embedding、语义分类器、打分或阈值。

`config/rules/agents.json` 是唯一机器规则源。

## 2. 三类检测证据

### Identity

Identity 覆盖四种输入，但原生 Author 与正文 attribution 使用两张允许重叠的规则表：

1. PR author identity；
2. commit author identity；
3. PR body / commit message 中 attribution grammar 抽出的 target；
4. 已登记的结构化 commit-message 身份声明。

PR author 与 commit author 都渲染为：

```text
login | name <email>
```

然后使用 `author_patterns` 扫描这个完整字符串。

文本 attribution 使用 `text_patterns`。它只在 attribution grammar 确定的有界片段中搜索。两张表允许重叠，但各自只扫描所属输入。

### Branch

只检查 PR `head_ref_name`，使用 `branch_patterns`。

### Label

只检查 PR 当前 labels，使用 `label_patterns`。历史 label event 不参与检测。

## 3. Attribution grammar

PR body 和 commit message 逐行处理。识别 attribution prefix 后，从前缀结尾开始提取当前句子或分句内的片段，再使用正文侧 matcher 搜索该片段。

普通前缀为：

```text
VERB_PATTERN + 至少一个空格 + CONNECTOR
```

当前动词模式：

```text
generated
implemented
authored
developed
written
created
assisted
built
made
coded
produced
autogenerated
reauthored
vibecoded / vibe-coded
co-authored / co authored / coauthored
co-developed / co developed / codeveloped
co-written / co written / cowritten
```

当前连接词：

```text
by
with
using
via
```

另外登记三种已有固定连字符形式：

```text
Generated-by
Co-authored-by
Co-developed-by
```

以下形式都可进入同一片段提取流程：

```text
Generated by Claude Code
Generated by: Claude Code
Generated-by Claude Code
Generated-by: Claude Code
Co-authored with Kiro
Co authored by Kiro
Coauthored using Kiro
Co-authored-by: Kiro
```

## 4. 片段提取与匹配

Attribution grammar 只确定“这里是身份声明上下文”，不直接判断 Agent。

片段从 attribution prefix 结尾开始，到行尾或当前句子、分句断点结束。英文 `. ! ? ;` 在其后为空白或行尾时构成断点，中文 `。！？；` 直接构成断点。冒号和 `assistance from`、`help of` 等普通内容保留在片段中，不再设置独立消费逻辑。

`text_patterns` 可在该片段的任意位置命中，但不会越过断点，也不会使用 Author 表反向补齐正文结果。身份边界拒绝邮箱域名、连字符词及 Unicode 单词内部的裸名碰撞，同时允许规则后接句末标点。

文本只做有限的表示层归一化：

```text
[visible](URL) -> visible (URL)
**Agent** -> Agent
__Agent__ -> Agent
*Agent* -> Agent
_Agent_ -> Agent
```

片段内成对的粗体/斜体标记会被移除；完整的反引号行内代码会被屏蔽，不作为身份声明。URL 与原始证据文本保持不变。

## 5. 结构化 message signature

当前有两条：

```regex
(?m)^🤖\s*Plandex\s*→
(?mi)^Replit-Commit-Author:\s*Agent\s*$
```

它们只扫描 commit message。虽然实现上是独立 signature pattern，但在结果分类中记为 Identity 证据。Aider 的 `(aider)` 形式保留在 `author_patterns` 中。

## 6. Branch 与 Label

Branch / Label 使用独立显式正则，不进入 Identity matcher。

例如：

```regex
(?:^|/)codex/
(?:^|/)trae/agent-
^codex$
```

## 7. 行为者归属

Identity 证据根据数字 actor id 区分：

- `target_author`：目标 PR 作者；
- `other_author`：PR 中其他 commit 作者；
- `unknown`：无法可靠确定行为者。

Branch / Label 记为 metadata，不自动归因给目标作者。
